# 智能路由改进方案

## 一、现状分析

### 现有架构

```
用户输入
    ↓
┌─────────────────────────┐
│  第一层：正则预检        │  ← `is_greeting_query()` 函数
│  (快速，无需 LLM)        │     13 个 GREETING_PATTERNS
└───────────┬─────────────┘
            ↓
      是问候语？
      ┌─────┴─────┐
      ↓           ↓
     YES          NO
      ↓           ↓
  GREETING     ┌─────────────────────────┐
  模式        │  第二层：LLM 判断        │  ← `SmartRouter.route()` 函数
  跳过 RAG    │  (需要调用 LLM)          │     3 个选项: RAG_ONLY / MEMORY_ONLY / HYBRID
              └───────────┬─────────────┘
                          ↓
                  ┌───────┴───────┐
                  ↓       ↓       ↓
              RAG_ONLY  MEMORY  HYBRID
                         ONLY
```

### 现有问题

| 问题 | 描述 |
|------|------|
| **提示词硬编码** | 提示词直接写在代码中，难以维护 |
| **输出格式复杂** | 3 个选项（RAG_ONLY / MEMORY_ONLY / HYBRID）增加误判风险 |
| **复用性差** | 没有统一管理，提示词分散 |
| **内存判断复杂** | MEMORY_ONLY / HYBRID 在实际场景中使用率低 |

## 二、改进方案

### 新架构

```
用户输入
    ↓
┌─────────────────────────┐
│  第一层：正则预检        │  ← `is_greeting_query()` 函数（保持不变）
│  (快速，无需 LLM)        │     增强：支持引号清理
└───────────┬─────────────┘
            ↓
      是问候语？
      ┌─────┴─────┐
      ↓           ↓
     YES          NO
      ↓           ↓
  NO_RAG       ┌─────────────────────────┐
  直接回答      │  第二层：LLM 判断        │  ← `SmartRouterV2.route()` 函数
               │  (简化：只需 1 次判断)   │     2 个选项: [YES] / [NO]
               └───────────┬─────────────┘
                           ↓
                     ┌─────┴─────┐
                     ↓           ↓
                   [YES]        [NO]
                     ↓           ↓
                   RAG         NO_RAG
                  检索        直接回答
```

### 核心改进

| 改进项 | 改前 | 改后 |
|--------|------|------|
| **提示词管理** | 硬编码在代码中 | 统一存放在 `prompts/system/` |
| **输出格式** | `RAG_ONLY / MEMORY_ONLY / HYBRID` | `[YES] / [NO]` |
| **判断复杂度** | 3 选 1 | 2 选 1 |
| **代码复用** | 无 | 支持多个智能体复用 |
| **版本控制** | 无 | 可独立版本管理 |

## 四、提示词对比

### 改前（硬编码）

```python
self.router_prompt_template = """你是一个智能路由助手，负责判断用户问题应该使用哪种检索方式。

【检索方式说明】
1. RAG_ONLY（知识库检索）：
   - 适用场景：查询客观知识、通用事实、教程文档
   - 示例："什么是变压器原理？"

2. MEMORY_ONLY（记忆检索）：
   - 适用场景：回顾个人历史、查询过往对话、个人偏好
   - 示例："我昨天问了什么？"

3. HYBRID（混合检索）：
   - 适用场景：需要结合知识库和个人记忆
   - 示例："根据我的偏好推荐 Python 教程"

【判断规则】
- 包含"我"、"昨天"、"之前"、"上次"、"记得"、"提醒"等词 → 优先考虑 MEMORY_ONLY 或 HYBRID
- 纯粹的知识查询，无个人化需求 → RAG_ONLY
- 既需要知识又需要个人化 → HYBRID

【用户问题】
{query}

【输出格式】
只输出以下三个选项之一，不要有任何其他内容：
RAG_ONLY
MEMORY_ONLY
HYBRID"""
```

### 改后（prompts/system/smart_router_v2_agent.md）

```markdown
# 智能路由智能体 V2 (Smart Router Agent V2)

## 角色定义

你是一个专业的智能路由助手，负责判断用户问题是否需要检索外部知识库。

## 判断规则

### 需要检索 [YES] 的情况

- 涉及具体事实查询（如"公司政策"、"规章制度"）
- 需要内部数据查询（如"去年营收"、"Q3销售冠军"）
- 特定产品规格或参数查询
- 需要精确信息的专业问题
- 涉及企业私有知识的问题

### 不需要检索 [NO] 的情况

- 闲聊、打招呼、感谢（如"你好"、"谢谢"）
- 通用编程问题（如"Python怎么读取CSV"、"什么是装饰器"）
- 创意写作（如"帮我写一首诗"、"讲个故事"）
- 翻译请求
- 简单计算
- 问候语（"在吗"、"最近怎么样"）
- 问身份问题（"你是谁"、"你能做什么"）

## 输出格式

**严格遵循以下格式，只输出 [YES] 或 [NO]，不要包含任何其他文字。**

## 判断示例

| 用户输入 | 判断 | 原因 |
|---------|------|------|
| "帮我写一首关于春天的诗" | [NO] | 创意写作 |
| "咱们公司去年的营收是多少？" | [YES] | 内部数据查询 |
| "Python里怎么读取CSV文件？" | [NO] | 通用编程问题 |
| "Q3季度的销售冠军是谁？" | [YES] | 内部数据查询 |
| "你好145" | [NO] | 闲聊问候 |
| "什么是HTTP协议？" | [NO] | 通用知识 |

## 重要原则

1. **只输出 [YES] 或 [NO]**，不要有任何其他文字
2. **不要输出推理过程**
3. **不要输出示例或说明**
4. **判断要一致**，相同类型的输入应该得到相同的判断
```

## 五、代码对比

### 改前（smart_router.py）

```python
class RouteMode(str, Enum):
    """路由模式枚举"""
    RAG_ONLY = "RAG_ONLY"          # 仅使用 RAG
    MEMORY_ONLY = "MEMORY_ONLY"    # 仅使用 Memory
    HYBRID = "HYBRID"              # 混合模式
    GREETING = "GREETING"          # 问候语

class SmartRouter:
    def __init__(self):
        # 提示词硬编码
        self.router_prompt_template = """..."""

    async def route(self, query: str) -> RouteMode:
        # 问候语检测
        if is_greeting_query(query):
            return RouteMode.GREETING

        # 调用 LLM
        decision = await llm_service.get_answer(...)

        # 解析 3 个选项
        if "RAG_ONLY" in decision:
            return RouteMode.RAG_ONLY
        elif "MEMORY_ONLY" in decision:
            return RouteMode.MEMORY_ONLY
        elif "HYBRID" in decision:
            return RouteMode.HYBRID
        else:
            return RouteMode.HYBRID  # 默认
```

### 改后（smart_router_v2.py）

```python
class RouteMode(str, Enum):
    """路由模式枚举"""
    RAG = "RAG"              # 需要检索
    NO_RAG = "NO_RAG"       # 不需要检索

class SmartRouterV2:
    def __init__(self):
        # 从文件加载提示词
        self._load_prompt_from_file()

    def _load_prompt_from_file(self):
        """从 prompts/system/ 目录加载提示词"""
        from pathlib import Path
        prompt_file = Path(__file__).parent.parent / "prompts" / "system" / "smart_router_v2_agent.md"
        if prompt_file.exists():
            self.router_prompt_template = prompt_file.read_text(encoding="utf-8")

    async def route(self, query: str) -> RouteMode:
        # 问候语预检（保持不变）
        if is_greeting_query(query):
            return RouteMode.NO_RAG

        # 调用 LLM
        decision = await llm_service.get_answer(...)

        # 解析 2 个选项
        if "[YES]" in decision:
            return RouteMode.RAG
        else:
            return RouteMode.NO_RAG
```

## 六、使用方式

### 前端需要修改吗？

**不需要。** 后端只需修改：
1. `RouteMode` 枚举值（`RAG_ONLY` → `RAG`）
2. API 响应格式（不变）

### 迁移步骤

1. ✅ **创建新文件**
   - `prompts/system/smart_router_v2_agent.md`
   - `services/smart_router_v2.py`

2. 🔄 **修改调用处**
   - 将 `from app.services.smart_router import smart_router` 改为
   - `from app.services.smart_router_v2 import smart_router_v2 as smart_router`

3. 🧪 **测试验证**
   - 测试问候语检测
   - 测试 [YES] / [NO] 判断

4. 🗑️ **可选：删除旧文件**
   - `smart_router.py`（保持兼容可暂不删除）

## 七、总结

### 优势

| 优势 | 说明 |
|------|------|
| **简化判断** | 从 3 选 1 简化为 2 选 1，减少误判 |
| **统一管理** | 提示词集中存放，便于维护和版本控制 |
| **职责清晰** | 第一层负责预检，第二层负责 LLM 判断 |
| **可扩展** | 未来可轻松添加更多智能体提示词 |

### 风险

| 风险 | 缓解措施 |
|------|----------|
| LLM 误判 | 保留正则预检层作为快速通道 |
| 性能影响 | 最小化，LLM 调用次数不变 |
| 兼容性 | 保持旧文件可选，逐步迁移 |
