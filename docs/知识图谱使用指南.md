# 知识图谱使用指南

## 🚀 快速开始

### 1. 创建索引（推荐，只需运行一次）

```bash
python create_neo4j_indexes.py
```

### 2. 正常使用系统

知识图谱功能已经完全自动化，无需手动操作！

## 📊 数据存储说明

### 自动化流程

```
用户操作 → 系统自动处理
```

#### 添加记忆/知识时：

1. **用户**：通过 API 或前端添加内容
2. **系统自动**：
   - 存储到 PostgreSQL（主存储）
   - 提取实体和关系（LLM）
   - 存储到 Neo4j（图谱）

#### 检索时：

1. **用户**：发起查询
2. **系统自动**：
   - 向量检索（PostgreSQL）
   - 图检索（Neo4j）
   - 融合结果返回

### 存储架构

```
PostgreSQL (主存储)
├── 完整文本内容
├── 向量嵌入
├── 用户信息
└── 元数据

Neo4j (知识图谱)
├── 实体 (Entity)
├── 关系 (RELATED)
└── 记忆链接 (可选)
```

## 🔧 配置说明

### 环境变量

```bash
# 启用知识图谱
ENABLE_KNOWLEDGE_GRAPH=True
ENABLE_ENTITY_EXTRACTION=True
ENABLE_RELATION_EXTRACTION=True

# Neo4j 连接
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_password
NEO4J_DATABASE=neo4j
```

### 功能开关

- `ENABLE_KNOWLEDGE_GRAPH=False`：完全禁用图谱功能
- `ENABLE_ENTITY_EXTRACTION=False`：仅禁用实体提取
- `ENABLE_RELATION_EXTRACTION=False`：仅禁用关系提取

## 📝 使用示例

### 1. 添加知识（自动构建图谱）

```python
# 通过语义记忆 API
POST /api/v1/memory/add
{
    "content": "张三在北京的阿里巴巴公司担任软件工程师",
    "role": "user",
    "importance": 0.9
}

# 系统自动：
# 1. 存储到 PostgreSQL
# 2. 提取实体：张三(PERSON), 北京(LOCATION), 阿里巴巴(ORGANIZATION), 软件工程师(CONCEPT)
# 3. 提取关系：张三-[工作于]->阿里巴巴, 阿里巴巴-[位于]->北京, 张三-[职业]->软件工程师
# 4. 存储到 Neo4j
```

### 2. 检索知识（自动混合检索）

```python
# 通过语义记忆 API
GET /api/v1/memory/retrieve?query=软件工程师&use_graph=true

# 系统自动：
# 1. 向量检索：找到语义相似的记忆
# 2. 图检索：通过实体关系找到相关记忆
# 3. 融合结果：返回综合排序的结果
```

### 3. 直接使用知识图谱 API

```python
# 构建图谱
POST /api/v1/knowledge_graph/build
{
    "text": "李四是产品经理，在深圳工作",
    "user_id": 1
}

# 混合检索
POST /api/v1/knowledge_graph/search
{
    "query": "产品经理",
    "top_k": 5,
    "vector_weight": 0.7,
    "graph_weight": 0.3
}

# 查询实体
POST /api/v1/knowledge_graph/query-entity
{
    "entity_name": "张三",
    "max_depth": 2
}

# 图统计
GET /api/v1/knowledge_graph/stats

# 图可视化
GET /api/v1/knowledge_graph/visualize?entity_name=张三
```

## 🐛 常见问题

### 1. 实体提取不准确

**原因**：LLM 理解偏差
**解决**：
- 使用更清晰的文本描述
- 检查 LLM 配置和 API Key
- 可考虑调整提示词

### 2. 关系提取缺失

**原因**：文本中关系不明显
**解决**：
- 使用更明确的关系表述
- 检查实体是否正确提取
- 可考虑手动补充关系

### 3. 检索结果不理想

**原因**：权重配置或数据质量
**解决**：
- 调整 `vector_weight` 和 `graph_weight`
- 增加更多相关数据
- 检查索引是否创建

### 4. 性能问题

**原因**：数据量大或缺少索引
**解决**：
- 运行 `create_neo4j_indexes.py`
- 考虑数据分片
- 添加缓存层
