# ReAct 智能体路由策略

## 核心设计理念

通过提示词设计，实现**智能路由决策**，让智能体能够自动判断：
- ✅ 何时直接使用 RAG（知识库检索）
- 🔄 何时先构建上下文再决策
- ❌ 何时直接回答（不需要工具）

## 路由决策流程

```
用户输入
    ↓
┌─────────────────────────┐
│  检测关键词              │
│  - 项目相关              │
│  - 知识库相关            │
│  - 企业私有知识          │
└─────────┬───────────────┘
          ↓
    ┌─────┴─────┐
    ↓           ↓
  包含关键词    不包含关键词
    ↓           ↓
┌───────────┐ ┌────────────────┐
│ 直接路由  │ │ 先构建上下文    │
│ 到 RAG    │ │ 再决策         │
└───────────┘ └────────────────┘
```

## 关键词分类

### 1. 项目相关 🔵
```
触发条件：包含以下任意关键词
- "我的项目"、"我们这个项目"、"项目"、"这个项目"
- "我们的产品"、"产品"、"这个产品"
- "我们的业务"、"业务"、"这项业务"

动作：立即使用 search_enterprise_knowledge
理由：用户明确在询问项目相关的内容，应该直接检索知识库
```

**示例：**
```
用户："你们这个项目用的什么技术栈？"
→ 路由：直接 RAG
→ 搜索：search_enterprise_knowledge("技术栈")
```

### 2. 知识库相关 🔵
```
触发条件：包含以下任意关键词
- "知识库"、"我们这个知识库"、"知识库内容"
- "上传了什么"、"有哪些文档"、"知识库有什么"
- "文档"、"资料"

动作：
- 询问文档列表 → 使用 list_knowledge_documents
- 询问具体内容 → 使用 search_enterprise_knowledge
```

**示例：**
```
用户："知识库里都有什么文档？"
→ 路由：直接 RAG
→ 工具：list_knowledge_documents({})

用户："帮我找找知识库里关于年假的资料"
→ 路由：直接 RAG
→ 工具：search_enterprise_knowledge("年假")
```

### 3. 企业私有知识 🔵
```
触发条件：包含以下任意关键词
- "公司"、"我们公司"、"咱们公司"
- "公司政策"、"规章制度"、"内部"
- "年假"、"报销"、"考勤"、"福利"

动作：立即使用 search_enterprise_knowledge
理由：这是企业私有知识，必须从知识库检索
```

**示例：**
```
用户："我们公司的年假是怎么规定的？"
→ 路由：直接 RAG
→ 搜索：search_enterprise_knowledge("年假政策")

用户："公司的报销流程是什么？"
→ 路由：直接 RAG
→ 搜索：search_enterprise_knowledge("报销流程")
```

### 4. 特定场景 🔵
```
触发条件：包含以下任意关键词
- "这个怎么用"、"如何使用"、"操作步骤"
- "配置"、"设置"、"怎么配置"
- "功能"、"有什么功能"、"能做什么"

动作：立即使用 search_enterprise_knowledge
理由：用户想要了解功能使用方法，需要检索知识库
```

## 第二优先级：先构建上下文再决策

### 什么时候触发？
- 用户输入**不包含**上述关键词
- 问题比较模糊，需要更多信息

### 决策流程

```
不包含关键词
    ↓
┌──────────────────────────┐
│ 步骤1：检查上下文         │
│ - 【上下文信息】是否包含答案│
│ - 历史对话是否相关         │
└───────────┬──────────────┘
            ↓
      ┌─────┴─────┐
      ↓           ↓
    有答案       无答案
      ↓           ↓
┌──────────┐ ┌────────────────┐
│ 直接回答 │ │ 步骤2：推断工具 │
└──────────┘ │ - 计算          │
             │ - 搜索          │
             │ - 代码执行      │
             │ - 闲聊         │
             └────────────────┘
```

### 场景决策表

| 场景 | 用户输入示例 | 决策 | 理由 |
|------|-------------|------|------|
| 打招呼 | "你好"、"在吗" | 直接回答 | 闲聊场景 |
| 闲聊 | "今天天气真好" | 直接回答 | 不需要工具 |
| 感谢 | "谢谢你的帮助" | 直接回答 | 礼貌回应 |
| 简单计算 | "100+200等于多少" | calculator | 需要计算 |
| 通用编程 | "Python怎么定义函数" | 代码工具 | 通用知识 |
| 创意写作 | "帮我写一首诗" | 直接回答 | 不需要RAG |
| 翻译 | "翻译这句话" | 翻译工具 | 需要工具 |
| 身份询问 | "你是谁"、"能做什么" | 直接回答 | 需要说明 |

## 优化建议

### 1. 关键词动态配置

可以将关键词放到配置文件中，便于调整：

```python
# config/routing_keywords.yaml
rag_keywords:
  project:
    - "项目"
    - "产品"
    - "业务"
  knowledge_base:
    - "知识库"
    - "文档"
    - "资料"
  enterprise:
    - "公司"
    - "政策"
    - "制度"
```

### 2. 软关键词 vs 硬关键词

- **硬关键词**（必须触发）：包含"我们"、"咱们"等明确指代
- **软关键词**（可能触发）：项目、政策等，可能需要结合上下文

### 3. 上下文优先级

```
高优先级（直接使用）：
1. 硬关键词命中 → 直接 RAG

中优先级（结合上下文）：
1. 检查历史对话
2. 检查用户偏好
3. 根据上下文推断

低优先级（默认行为）：
1. 通用问题直接回答
2. 技术问题使用代码工具
3. 计算问题使用计算器
```

## 优势

1. **简单清晰**：通过提示词即可控制路由逻辑
2. **灵活调整**：修改提示词即可改变路由策略
3. **易于测试**：可以针对关键词进行单元测试
4. **可追溯**：每一步都有 Thought 记录，便于调试
5. **降级方案**：关键词未命中时，有默认的上下文构建流程

## 注意事项

1. **关键词冲突**：如果一个句子包含多个关键词，按优先级选择
2. **模糊表达**：如果用户表达模糊，优先构建上下文
3. **迭代限制**：最多 {max_iterations} 次推理，达到上限必须给出答案
4. **空结果处理**：搜索2次仍无结果时，承认知识库为空，不要反复搜索
