# 日志系统集成指南

## 概述

本项目实现了完整的日志系统，支持系统日志记录、用户操作追踪、分级权限控制等功能。普通用户只能查看自己的日志，企业管理员可以查看所有日志。

## 系统架构

### 核心组件

1. **数据模型** (`app/models/system_log.py`)
   - `SystemLog`: 系统日志表，记录所有系统事件
   - `UserActionLog`: 用户操作日志表，专门记录用户业务操作
   - `LogLevel`: 日志级别枚举 (DEBUG, INFO, WARNING, ERROR, CRITICAL)
   - `LogCategory`: 日志分类枚举 (USER_ACTION, SYSTEM_EVENT, API_REQUEST等)

2. **服务层** (`app/services/log_service.py`)
   - `LogService`: 提供日志记录、查询、统计等核心功能
   - 支持多维度查询和分页
   - 自动权限控制

3. **装饰器** (`app/utils/log_decorators.py`)
   - `@log_function_call`: 自动记录函数调用日志
   - `@log_user_action`: 自动记录用户操作日志
   - 支持性能监控和错误追踪

4. **API接口** (`app/api/v1/endpoints/logs.py`)
   - 日志查询接口
   - 统计分析接口
   - CSV导出功能
   - 日志清理功能（管理员）

5. **中间件** (`app/middleware/logging_middleware.py`)
   - 自动记录所有API请求
   - 性能监控
   - 错误追踪

## 快速开始

```python

```

### 3. 在路由中注册日志API

```python

app.include_router(logs.router, prefix="/api/v1/logs", tags=["logs"])
```

## 使用方法

### 1. 手动记录日志

```python
from app.services.log_service import log_service
from app.models.system_log import LogLevel, LogCategory

# 记录系统日志
await log_service.create_system_log(
    level=LogLevel.INFO,
    category=LogCategory.SYSTEM_EVENT,
    action="user_login",
    message="用户登录成功",
    user_id=user.id,
    session_id=session_id,
    ip_address="192.168.1.100"
)

# 记录用户操作日志
await log_service.create_user_action_log(
    user_id=user.id,
    action_type="DOCUMENT_UPLOAD",
    action_name="上传文档",
    description="用户上传了PDF文档",
    resource_type="document",
    resource_id=document.id,
    resource_name=document.name,
    success=True

```

```python
async def create_knowledge_base(name: str, description: str, user_id: str):

    action_name="创建知识库",
    resource_type="knowledge_base",
    description="用户创建了新的知识库",
    log_data_changes=True
)

    # API端点逻辑
    pass
```

### 3. 查询日志

```python
# 查询系统日志
logs = await log_service.get_system_logs(
    user_id=user.id,  # 普通用户只能查看自己的

    user_id=user.id,

```

## API接口使用

### 1. 查询系统日志

```http

Authorization: Bearer <token>
```

### 2. 查询用户操作日志


### 3. 获取统计信息

```http

Authorization: Bearer <token>
```

### 4. 导出日志（CSV格式）

```http
GET /api/v1/logs/export/csv?log_type=system&level=ERROR&start_time=2024-01-01T00:00:00Z

```

### 5. 清理旧日志（仅管理员）

```http
DELETE /api/v1/logs/cleanup?days=90
Authorization: Bearer <admin_token>
```

## 权限控制

### 用户角色

1. **普通用户**
   - 只能查看自己的日志
   - 不能查看敏感信息（IP地址、用户代理等）
   - 不能执行管理操作

2. **企业管理员** (`user.is_admin = True`)
   - 可以查看所有用户的日志
   - 可以查看完整的敏感信息
   - 可以执行日志清理等管理操作
   - 可以导出完整的日志数据

### 设置管理员

```sql
-- 将用户设置为管理员
UPDATE users SET is_admin = TRUE WHERE email = 'admin@example.com';
```

## 性能优化

### 1. 数据库索引

系统已自动创建以下索引：
- 时间索引：`idx_system_logs_created_at`
- 用户索引：`idx_system_logs_user_id`
- 复合索引：`idx_system_logs_user_time`
- 分类索引：`idx_system_logs_category_level`

### 2. 异步日志记录

所有日志记录都是异步执行，不会阻塞主业务流程：

```python
# 异步记录，不等待完成
asyncio.create_task(
    log_service.create_system_log(...)
)
```

### 3. 日志清理

定期清理旧日志以保持性能：

```python
# 清理90天前的日志
await cleanup_old_logs(days=90)
```

## 最佳实践

### 1. 日志级别使用

- `DEBUG`: 详细的调试信息，生产环境通常不记录
- `INFO`: 一般信息，如用户操作、系统状态变化
- `WARNING`: 警告信息，如参数验证失败、资源不足
- `ERROR`: 错误信息，如异常、失败的操作
- `CRITICAL`: 严重错误，如系统崩溃、数据丢失

### 2. 敏感信息处理

```python
# 在装饰器中指定敏感参数
@log_function_call(
    sensitive_params=["password", "token", "secret_key"]
)
async def authenticate_user(username: str, password: str, token: str):
    pass
```

### 3. 批量操作日志

```python
# 对于批量操作，记录汇总日志而不是每个项目
@log_user_action(
    action_type="BATCH_OPERATION",
    action_name="批量删除文档"
)
async def batch_delete_documents(document_ids: List[str], user_id: str):
    success_count = 0
    error_count = 0
    
    for doc_id in document_ids:
        try:
            await delete_document(doc_id)
            success_count += 1
        except Exception:
            error_count += 1
    
    # 记录汇总结果
    await log_service.create_user_action_log(
        user_id=user_id,
        action_type="BATCH_DELETE",
        action_name="批量删除文档",
        description=f"成功删除{success_count}个文档，失败{error_count}个",
        success=error_count == 0,
        extra_info={
            "total_count": len(document_ids),
            "success_count": success_count,
            "error_count": error_count
        }
    )
```

## 故障排除

### 1. 日志记录失败

如果日志记录失败，检查：
- 数据库连接是否正常
- 表结构是否正确创建
- 用户权限是否足够

### 2. 性能问题

如果日志查询缓慢：
- 检查数据库索引是否创建
- 考虑增加分页限制
- 定期清理旧日志

### 3. 权限问题

如果用户无法查看日志：
- 检查用户的`is_admin`字段
- 确认API权限验证逻辑
- 检查日志查询的用户ID过滤
